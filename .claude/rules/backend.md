# Backend rules (apps/api)

## Language & layout

- Go, module `github.com/vianbas/finwatch/apps/api`.
- Entrypoint: `cmd/api`. Application code lives under `internal/`.
- `internal/platform/*` holds infrastructure (HTTP server, PostgreSQL). Feature
  modules get their own `internal/<module>` package and are wired in
  `internal/platform/httpserver/router.go`.
- This is a **modular monolith**: modules talk through Go interfaces in-process,
  not over the network. Do not split into services.

## Data & types

- PostgreSQL access via **pgx**; typed queries generated by **sqlc**. **No ORM.**
- All SQL changes go through **versioned migrations** in `migrations/`
  (`<version>_<name>.up.sql` + `.down.sql`). Migrations are immutable once merged.
- **Money:** integer minor units in `BIGINT` (Go `int64`). Never float.
- **Time:** `TIMESTAMPTZ` in UTC; serialise as RFC 3339 at boundaries.

## HTTP

- Routing via chi (`github.com/go-chi/chi/v5`), stdlib `net/http` compatible.
- Every server has explicit, bounded timeouts (read header/read/write/idle).
- Standard middleware chain: request ID → panic recovery → access log.
- Errors use the canonical envelope `{"error":{"code","message"}}` and must
  match `contracts/openapi.yaml`.
- Shutdown is graceful and bounded by `HTTP_SHUTDOWN_TIMEOUT`.

## Configuration

- All config comes from environment variables, loaded and **validated at
  startup** in `internal/config`. Invalid config is fatal (fail fast).
- Do not read `os.Getenv` outside `internal/config`.

## Logging

- Structured JSON via `log/slog`. No `fmt.Println`. Never log secrets, tokens,
  or raw personal/financial data.

## Testing

- Table-driven tests with the standard `testing` package.
- Keep tests hermetic: config tests inject `getenv`; HTTP tests use `httptest`
  and fakes rather than a live database.

## Quality gates (must pass before commit)

`gofmt -l` clean · `go vet ./...` · `go test ./...` · `go build ./...`
